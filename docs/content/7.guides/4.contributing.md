## Layout

| Path | Contents |
|---|---|
| `src/` | the `vld` core crate |
| `crates/vld-*` | integration crates (each with `src/`, `tests/`, usually `examples/`) |
| `tests/all/` | core integration tests (one binary) |
| `benches/` | Criterion benchmarks |
| `fuzz/` | `cargo-fuzz` targets (not in the workspace) |
| `examples/playground` | a small app that uses many crates together |
| `docs/` | this site (Nuxt + Nuxt Content) |
| `scripts/` | CI and release scripts |

All crates share one version and are released together; see `PUBLISHING.md`.

## Running CI locally

`scripts/ci-all.sh` is both the local runner and the command source of the GitHub workflow.

```bash
scripts/ci-all.sh                 # every group
scripts/ci-all.sh test clippy     # only these groups
```

| Group | What it does |
|---|---|
| `test` | workspace tests and doctests |
| `features` | the core with each date backend and every feature combination |
| `integrations` | integration crates with their dual-major feature branches |
| `clippy` | clippy with `-D warnings` |
| `docs` | `cargo doc` with `-D warnings` |
| `deny` | `cargo deny` (licenses, advisories) |
| `msrv` | every crate on its `rust-version` (see [MSRV](/getting-started/msrv)) |
| `minimal` | minimal dependency versions |
| `fmt` | `cargo fmt --check` |
| `package` | `cargo package` dry runs |
| `fuzz` | builds the fuzz targets |
| `wasm` | wasm32 builds of the UI integrations |
| `playground` | the playground example |

Every step runs even after a failure, and a summary is printed at the end. Steps whose tool or toolchain is missing are skipped with a note. Builds use the committed `Cargo.lock` (`--locked`) and the `ci` profile (no debuginfo, no incremental).

::warning
Never use `--all-features` on crates with dual-major features (`ntex-3` / `ntex-4`, `utoipa-5` / `utoipa-6`, `sqlx-0_8` / `sqlx-0_9`, …): the majors are mutually exclusive and fail with `compile_error!`.
::

## Keeping target/ small

With ~30 integration crates a debug `target/` grows fast. The workspace already helps:

- `[profile.dev]` uses `debug = "line-tables-only"` for workspace crates and no debuginfo for dependencies;
- `split-debuginfo = "off"` stops macOS from leaving stale object files in `target/*/deps` on every rebuild;
- `scripts/ci-all.sh` builds into `target/ci` and deletes it at the end (keep it with `VLD_CI_KEEP_TARGET=1`).

If it still grows, remove old artifacts with [`cargo sweep`](https://github.com/holmgr/cargo-sweep):

```bash
cargo install cargo-sweep
cargo sweep --time 7     # delete artifacts not used for 7 days
```

## Snapshot tests

`vld-utoipa`, `vld-aide` and `vld-ts` use [insta](https://insta.rs) snapshots. After an intended output change:

```bash
cargo insta test -p vld-ts
cargo insta review
```

## vld-ts cross-check against Node

`vld-ts` can compare its generated Zod / Valibot schemas against real Node runs. Point `VLD_TS_NODE_DIR` at a directory with `zod@3` and `valibot@1` installed:

```bash
mkdir -p .ts-check && npm --prefix .ts-check install zod@3 valibot@1
VLD_TS_NODE_DIR=$PWD/.ts-check cargo test -p vld-ts
```

Without the variable the cross-check is skipped.

## Live Redis and RabbitMQ tests

`vld-redis` and `vld-lapin` have tests against real servers. They run when the URL is set:

```bash
docker run -d -p 6379:6379 redis:7
docker run -d -p 5672:5672 rabbitmq:3
REDIS_URL=redis://127.0.0.1:6379 cargo test -p vld-redis
AMQP_URL=amqp://guest:guest@127.0.0.1:5672/%2f cargo test -p vld-lapin
```

## Fuzzing

```bash
cargo install cargo-fuzz
cd fuzz
cargo +nightly fuzz list
cargo +nightly fuzz run iso_formats -- -max_total_time=60
```

Targets: `iso_formats`, `string_formats`, `url_decode`, `error_truncation`. Crashes are saved to `fuzz/artifacts/<target>/`.

## Documentation

This site lives in `docs/` and is built with Nuxt Content:

```bash
cd docs
pnpm install
pnpm dev                                   # http://localhost:3000
NUXT_APP_BASE_URL=/vld/ pnpm generate      # static build in .output/public
pnpm preview                               # serve the build like GitHub Pages
```

`CHANGELOG.md` and `MSRV.md` are copied into the site by `docs/scripts/sync.mjs`; edit the originals. The site is deployed to GitHub Pages by `.github/workflows/docs.yml`.

Rust API docs: `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps` must stay clean.

## Changelog

Add entries under `## [Unreleased]` at the top of `CHANGELOG.md` (create the heading if it is not there), and a line in "Migration" for anything breaking.
