With the `derive` feature, `#[derive(Validate)]` generates the same API as `schema!` from attributes on an ordinary struct. Use it when the struct already has other derives (`serde`, `clap`, `utoipa`) or you prefer attributes.

```toml [Cargo.toml]
vld = { version = "0.5", features = ["derive"] }
```

```rust
use vld::prelude::*;
use vld::Validate;

#[derive(Debug, serde::Serialize, serde::Deserialize, Validate)]
#[serde(rename_all = "camelCase")]
struct SignUp {
    #[vld(vld::string().min(2).max(50))]
    display_name: String,
    #[vld(vld::string().email())]
    email_address: String,
    #[vld(vld::number().int().gte(18).optional())]
    age: Option<i64>,
}

let s = SignUp::vld_parse(r#"{"displayName": "Ada", "emailAddress": "ada@example.com"}"#).unwrap();
assert_eq!(s.age, None);
```

Every field needs a `#[vld(...)]` attribute with a schema expression (except `#[serde(skip)]` fields). The expression is pasted as is, so the paths must be in scope.

## Generated API

| Item | Notes |
|---|---|
| `T::vld_parse(input)` | named `vld_parse`, not `parse`, so it does not clash with `clap::Parser::parse` and similar derives |
| `T::parse_value(&value)` / `T::vld_parse_value(&value)` | parse a `serde_json::Value` |
| `impl VldParse for T` | used by all integration crates |
| `T::validate(&instance)` / `T::is_valid(&instance)` | check a `Serialize` value |
| `T::json_schema()` / `T::to_openapi_document()` | feature `openapi` |
| `T::validate_fields(..)` / `T::parse_lenient(..)` (+ `_value` variants) | only with `#[vld(lenient)]` |

## Serde attributes

| Attribute | Effect |
|---|---|
| struct `rename_all = "..."` | `lowercase`, `UPPERCASE`, `camelCase`, `PascalCase`, `snake_case`, `SCREAMING_SNAKE_CASE`, `kebab-case`, `SCREAMING-KEBAB-CASE`; also `rename_all(serialize = "...", deserialize = "...")` |
| field `rename = "..."` | also `rename(serialize = "...", deserialize = "...")` |
| field `skip` / `skip_deserializing` | not validated, set to `Default::default()` |
| field `default` / `default = "path"`, struct `default` | a **missing** key takes the default without running the schema (as serde does); a present key is validated |
| `flatten`, `alias` | compile error (not supported) |

Parsing and JSON Schema use the **deserialize** names; `validate()` uses the **serialize** names. See [parse vs validate](/structs/parse-vs-validate).

## Generics

Generic structs work. Their field schemas are rebuilt on every call (non-generic structs cache them, see below).

```rust
use vld::schema::VldParse;

#[derive(Debug, Validate)]
pub struct Page<T: VldParse> {
    #[vld(vld::array(vld::nested(T::vld_parse_value)))]
    pub items: Vec<T>,
}
```

## Lenient parsing

`#[vld(lenient)]` on the struct adds `validate_fields()` and `parse_lenient()`. Every field type must implement `Default` and `Serialize`. See [Lenient parsing](/structs/lenient).

```rust
#[derive(Debug, Default, serde::Serialize, Validate)]
#[vld(lenient)]
struct Config {
    #[vld(vld::string().min(1))]
    host: String,
    #[vld(vld::number().int().min(1).max(65535))]
    port: i64,
}

let r = Config::parse_lenient_value(&serde_json::json!({"host": "h", "port": 0})).unwrap();
assert_eq!(r.error_count(), 1);
assert_eq!(r.value.port, 0); // invalid field fell back to Default
```

## OpenAPI parameters

For `utoipa::IntoParams`, add `#[into_params(parameter_in = Query)]` (or `Path`, `Header`, `Cookie`) to the struct; the derive records it and [`vld-utoipa`](/integrations/openapi/utoipa) uses it.

## Caching

Field schemas of non-generic structs are built once per process and cached, exactly as with [`schema!`](/structs/schema-macro#schema-caching): they must be `Send + Sync + 'static`, and values captured on first use are frozen.
